# ADR-0026: 괴리는 상승/하락 색, 조치 여부는 같은 계열 강조 — 기준 10%p, 리밸런싱 상태 컬럼 추가

## Status
Accepted (ADR-0008을 대체)

## Context

비중 체크 페이지의 "차이" 컬럼은 `diffColor`가 색을 결정했는데, 이 함수가 **기준 초과 여부까지 함께 판단**하고 있었다:

- `|diff| < 기준` → 민트(GOOD_COLOR)
- `diff > 0` → 주황
- `diff < 0` → 빨강

여기엔 두 가지 문제가 있었다.

첫째, **색이 국내 증권 앱의 상승/하락 감각과 반대**였다. 국내에서 빨강은 상승(+), 파랑은 하락(−)인데, 이 팔레트는 하락에 빨강을 쓰고 상승엔 주황을 썼다. 매일 증권 앱을 보는 사용자에게 `-12%p`가 빨간색으로 보이는 건 반사적으로 잘못 읽힌다.

둘째, **하나의 색이 두 가지 정보를 겸했다.** "숫자가 얼마나 벗어났나(부호·크기)"와 "그래서 조치가 필요한가(기준 초과)"는 별개의 질문인데, 색 하나가 둘을 동시에 표현하니 기준 미달 구간에서는 부호 정보가 사라졌다(+3%p와 −3%p가 똑같은 민트색). 게다가 바로 옆 "조치 필요액" 컬럼도 같은 `diffColor`를 쓰고 있어서 한 행이 통째로 한 색으로 뭉쳤다.

기준값 자체도 5%p는 지나치게 민감해서 웬만한 변동에도 리밸런싱 필요가 떴다.

## Decision

**1. 색 함수를 두 개로 분리한다.**

- `diffColor(diff)` — **부호만** 본다. `+` → 상승색, `−` → 하락색, `0` → muted. `REBALANCE_THRESHOLD`를 참조하지 않는다. 작은 상승도 상승이다.
- `actionColor(diff)` — **판정**의 색. "매도 필요" 라벨과 조정 금액에 쓴다. 같은 `diff`에 대해 `diffColor`와 **항상 같은 색 계열**이어야 한다 — hue와 채도는 그대로 두고 **명도만 한 단계** 옮긴 변형을 쓴다. 한 행의 숫자와 판정이 서로 무관한 두 신호가 아니라 하나의 신호로 읽혀야 하기 때문이다.
- 기준 미달(`유지`)은 조치가 필요 없으므로 상승/하락 스케일에서 아예 빠지고 **본문 텍스트 색**(`var(--foreground)`)을 쓴다. 민트(GOOD_COLOR)를 쓰면 한 행에 계열이 다른 세 번째 hue가 끼어들어 "같은 계열" 규칙이 깨진다.

**2. 국내 시장 관례를 따른다: 플러스는 빨강, 마이너스는 파랑.** 미국식 green-up/red-down의 반대이므로 "버그"로 보고 되돌리지 말 것.

**3. 색값은 테마별 CSS 변수로 둔다** (`--diff-rise`, `--diff-fall`, `--diff-rise-strong`, `--diff-fall-strong`). 하드코딩된 한 쌍으로는 거의 흰 카드와 어두운 카드 양쪽에서 읽히지 않는다 — 특히 채도 높은 파랑은 다크 카드 위에서 명암비가 3:1 아래로 떨어져서, 다크 테마에서는 밝게 올려야 한다. "강조"는 양쪽 테마에서 **배경으로부터 더 멀어지는 방향**(라이트=더 진하게, 다크=더 밝게)으로 정의하되, **명도 한 단계만** 움직여 같은 계열로 보이는 범위를 넘지 않는다. 모든 조합은 sRGB 색역 안에 있고 카드 배경 대비 4.2:1 이상이다.

**4. `REBALANCE_THRESHOLD`를 5%p → 10%p로 올린다.**

**5. 매수/매도 방향은 전용 `리밸런싱` 상태 컬럼이 말한다.** 조정 금액 바로 왼쪽에 유지/매수 필요/매도 필요를 두고, 금액 자체는 **부호 없이** 절댓값으로 표시한다. 처음에는 금액에 `+`/`−` 부호를 붙였지만(초안), 방향을 알려주는 컬럼이 바로 옆에 있으면 부호는 같은 정보를 두 번 말하는 것이고 "차이는 +인데 금액은 −"라는 혼란만 남는다.

또한 금액 컬럼 이름은 `조치 필요액`이 아니라 **`조정 금액`**으로 둔다 — 왼쪽 상태 컬럼이 이미 "필요"를 말하고 있어 중복이고, `조정`은 매매뿐 아니라 현금성 자산의 증감까지 포괄한다.

**6. 자산군 테이블은 목표 비중 내림차순으로 정렬한다.** 포트폴리오가 "어떤 모양이어야 하는가"의 순서로 읽히고, 시세가 움직여도 행 순서가 흔들리지 않는다. 괴리 큰 순 정렬은 요약 카드(트리아지 목록)에만 남긴다.

ADR-0008의 "통계 카드는 기준 초과 항목만 개수+이름으로 나열" 결정은 그대로 유효하다 — 그 카드는 `actionColor`를 쓴다.

## Consequences

- 한 행의 차이 수치와 조치 판정이 같은 계열 안에서 명도만 다르므로, "얼마나 벗어났나"와 "조치가 필요한가"를 하나의 신호로 묶어 읽으면서도 둘을 구분할 수 있다.
- `유지` 행은 차이만 상승/하락색이고 판정·금액은 본문색이다 — 조치가 필요 없다는 사실이 색의 부재로 드러난다.
- 부호의 의미가 기준 미달 구간에서도 유지된다 — 목표에 근접해 있어도 어느 방향으로 붙어 있는지 보인다.
- 매수/매도 방향이 컬럼 하나로 명시되므로 금액에서 부호를 읽어낼 필요가 없다. 대가로 컬럼이 하나 늘어나 자산군 컬럼 너비를 줄였고(이름은 truncate), 테이블 전체 폭은 그대로 유지했다.
- 기준이 10%p로 올라가 "리밸런싱 필요" 알림이 줄어든다. 놓치는 구간이 넓어지는 대가가 있으므로, 사용자별 조절 가능성은 PRD의 열린 질문으로 남긴다.
- 보유 종목 페이지의 **수익률 색은 이 규칙을 따르지 않는다** (`returnColor`: 이익=민트, 손실=빨강). 즉 빨강이 비중 체크에서는 "목표보다 높음", 보유 종목에서는 "손실"을 뜻해 앱 안에서 의미가 갈린다. 수익률까지 국내 관례(이익=빨강, 손실=파랑)로 맞출지는 별도 결정으로 남겨둔다.
