# ADR-0044: holdings.qty/avg_price는 매매일지를 통해서만 바뀐다 (보유종목 화면은 읽기 전용)

## Status
Partially superseded by [ADR-0048](./0048-opening-balance-no-date.md)(기초잔고는 날짜 없이, 캘린더에서 제외) and [ADR-0049](./0049-execution-row-inline-actions.md)(상세 모달 대신 인라인 수정/삭제, intent 유지 로직도 체크박스 기반으로 대체). holdings.qty/avg_price가 매매일지를 통해서만 바뀐다는 핵심 결정 자체는 유지된다.

## Context

ADR-0027은 "체결 원장이 보유 수량·평균매입가를 바꾸는 유일한 경로"라고 정하면서도, 원래 설계가 요구한 "수동 보유 편집 UI 제거"는 하지 않았다 — 이 앱에 이미 핵심 UX로 자리 잡은 모달 편집(ADR-0006/0007/0014/0015)과 매매일지 도입 전 데이터를 감안한 절충이었다.

그 절충이 실제로 문제를 냈다. `lib/api/holdings.ts`의 `insertHolding`/`updateHolding`은 `holdings.qty`/`avg_price`를 `executions`와 전혀 무관하게 직접 write한다. 실제 데이터를 점검해보니:
- **뱅가드 S&P500 ETF**: `holdings.qty = 20`인데 체결이 0건 — 보유종목 화면에서 등록한 수량이 체결 원장에 전혀 반영되지 않은 상태였다. 이 상태로 매매일지에 이 종목의 체결을 하나라도 기록하면, 리플레이가 체결만 보고 수량을 다시 계산해 20을 조용히 지워버렸을 것이다.
- **앱셀레라 바이오로직스**: 체결 원장을 리플레이하면 18주인데 `holdings.qty = 7` — 기초잔고 체결의 수량이 오타(정정: 7이 맞음)였는데, holdings 값을 신뢰할 방법이 없어 우연히 발견했다.

두 write 경로(보유종목 직접 수정 vs. 체결 리플레이)가 동시에 존재하는 한 이런 드리프트는 계속 재발한다.

## Decision

**holdings.qty/avg_price를 바꾸는 화면을 매매일지 하나로 통일한다.** 보유종목 화면(`/holdings`)의 종목 추가/수정 모달(`HoldingFormDialog`)에서 수량·평균매입가 입력을 완전히 제거했다 — 새 종목은 항상 수량 0으로 생성되고, 매매일지에서 첫 체결을 기록해야 채워진다. 이름·티커·자산군·계좌·구분·메모 수정과 종목 삭제는 그대로 보유종목 화면에 남는다 — 매매/보유량과 무관한 메타데이터라서 굳이 매매일지를 거칠 이유가 없다.

**"이미 보유하고 있던 종목 등록" 체크박스.** 매매일지의 "+ 새 종목" 흐름에 체크박스를 추가했다 — 체크하면 그 체결의 `intent`가 `'NEW'`가 아니라 `'OPENING_BALANCE'`로 저장된다. 실제 매매가 아니라 이월 잔고를 기록하는 것임을 구분해 매매 횟수·보유일수 같은 집계가 왜곡되지 않게 한다(순수 `NEW`로 뭉뚱그리면 이 정보가 사라진다는 걸 초기 설계 검토 때 발견했다).

**기초잔고 체결을 매매일지에 그대로 보여준다 (ADR-0027 이후 처음 뒤집는 부분).** 예전엔 `intent === 'OPENING_BALANCE'`인 행을 일지 목록에서 숨겼다. 이제는 보여주되 "기초잔고" 배지를 붙인다 — 숨기면 나중에 수정할 방법이 없어지는데(체크박스로 만든 다음엔 목록에 없으니 클릭할 수도 없다), 보이게 하면 다른 체결처럼 상세 모달 → 수정으로 그냥 고칠 수 있다. `TradeSummaryStrip`의 매수/매도 합계 집계에서는 여전히 제외한다 — 실제 그 기간에 일어난 매매가 아니므로.

**현금성 자산(예적금 등, ticker 없음) 등록도 매매일지로 옮긴다.** ADR-0022가 `HoldingFormDialog`에 만들었던 KRW/$ 체크박스(코드 없이 종목명·금액만으로 등록)를 매매일지의 "+ 새 종목" 흐름으로 그대로 옮겼다 — 수량·평단가와 마찬가지로 예외를 두지 않는다. `HoldingFormDialog`는 기존 현금성 종목을 편집할 때 티커 입력을 계속 비활성화해 둘 뿐, 새로 만들거나 금액을 바꾸는 기능은 없다.

**체결 수정 시 `intent`가 조용히 덮어써지던 버그를 고쳤다.** `ExecutionFormDialog.handleSubmit`이 수정 모드에서도 항상 `intent: 'NEW'`를 써서, 기초잔고 체결을 수정(예: 수량 오타 수정)하면 `OPENING_BALANCE` 표시가 사라지는 버그가 있었다. 이제 수정 모드는 `editingExecution.intent`를 그대로 유지한다.

**매수 메모 프리필 / 매도 시 매수 이력 읽기 전용 표시.** 같은 종목에 매수를 추가할 때, 근거 textarea가 비어 있으면 그 종목의 가장 최근 매수 메모를 프리필한다. 매도 화면에서는 그 종목의 매수 체결에 달린 메모들을 날짜순으로 읽기 전용 표시한다 — ADR-0033의 "매도 시 매수 근거 노출" 취지를 되살리되, POSITION 노트 하나가 아니라 **체결마다 쌓인 여러 메모**를 보여주므로 라지가 시간에 따라 어떻게 바뀌었는지 더 잘 드러난다.

**메모 필드 추가.** `HoldingFormDialog`에는 있는데 매매일지 "새 종목" 흐름엔 없던 메모 입력을 추가해 두 화면의 입력 디테일을 맞췄다.

## Consequences

- 데이터 정합성 확인 결과 발견된 두 건(뱅가드 S&P500 ETF 기초잔고 누락, 앱셀레라 바이오로직스 수량 오타)을 이번에 직접 수정했다 — 지금은 모든 보유 종목이 체결 리플레이 결과와 정확히 일치한다.
- `lib/api/holdings.ts`의 `insertHolding`/`updateHolding`은 함수 시그니처를 안 바꿨다 — `replayAndPersistHolding`(`lib/journal/commit.ts`)이 리플레이 결과를 쓸 때 여전히 이 함수를 쓴다. UI 레이어만 qty/avgPrice를 더 이상 사용자 입력으로 채우지 않는다(새 종목은 0/0 하드코딩).
- ADR-0022(현금성 자산 체크박스)의 "만드는" 부분은 이 ADR로 대체됐다 — `HoldingFormDialog`는 이제 기존 현금성 종목을 읽기/메타데이터 수정할 때만 그 상태를 존중한다.
- `docs/PRD.md`도 갱신했다 — 보유종목 화면 항목에 "여기서는 종목 정보만 관리하고 수량/평단가는 매매일지에서만 바뀐다"를 명시했다.

## 대안

- **보유종목 화면에 "기초잔고 수정" 전용 진입점을 별도로 둔다**: 검토했지만, 기초잔고 체결을 매매일지에 그대로 보여주기로 하면서 불필요해졌다 — 이미 있는 "체결 클릭 → 상세 → 수정" 경로가 그대로 그 역할을 한다.
