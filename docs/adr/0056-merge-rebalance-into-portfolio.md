# ADR-0056: "비중 체크" 페이지를 없애고 포트폴리오 화면에 흡수한다

## Status
Accepted

## Context

ADR-0023이 `/rebalance`("비중 체크")에서 `/portfolio`(당시 `/setup`)와 중복되는 표시를 걷어낸 뒤로, 두 화면은 서로 다른 것만 보여주는 상호보완 관계였다 — 포트폴리오는 "모양"(목표/실제 도넛, 자산군별 종목 구성), 비중 체크는 "숫자와 판정"(자산군별 목표%/실제%/차이/조정 금액 표)이었다.

그런데 "지금 리밸런싱해야 하나?"처럼 가벼운 확인을 하고 싶을 때조차 별도 페이지로 이동해야 했다. 포트폴리오라는 같은 도메인 안에서 바로 확인되는 게 페이지 전환이 아예 없다는 점에서 더 가벼운 경험이라고 판단했다 — ADR-0023의 "같은 숫자를 다른 그래프로 반복 표시하지 말 것"과는 다른 층위의 문제(정보구조/내비게이션)다.

## Decision

**비중 체크의 내용을 별도 탭이 아니라, 포트폴리오의 기존 자산군 카드 구조에 직접 얹는다.** 탭으로 나누는 방안도 검토했지만(포트폴리오의 draft 편집 모드와 상태가 꼬일 수 있어 그 자체로 문제를 풀 수는 있었다), 그보다도 두 화면이 애초에 겹치지 않고 상호보완적이었다는 점에 착안해 **하나의 시각화로 합치는 쪽**을 택했다:

- **`GroupCard`의 접힌 줄**에 목표%/실제%/차이를 고정폭 컬럼(라벨 위·값 아래, `w-16`)으로 노출한다. 차이는 `diffColor`(부호 기반, ADR-0026)로만 표시하고, 화면 전환 없이 카드 목록만 훑어도 리밸런싱 필요 여부가 보인다. **이 차이는 "%p"로 이 색을 재사용하는 게 맞는지 논의했다** — 엄밀히는 주가 상승/하락이 아니라 비중 초과/미달이라 다른 색 체계를 새로 만드는 방안도 검토했지만, 색 체계를 하나 더 늘리는 것보다 "양수=빨강/음수=파랑"이라는 기존 규칙의 의미를 조금 넓혀(희석해) 그대로 재사용하는 쪽을 택했다(일관성 우선).
- **`GroupHoldingsPanel`(펼친 뷰)의 종목 목록 맨 아래에 합계 행**을 추가한다 — 그 자산군의 목표 금액·평가금 합계·**조정금**(=`actionAmount`)을 테이블의 합계처럼 보여준다. `GroupCalc.actionAmount`가 이미 정확히 이 계산값이라 새 계산은 필요 없었다. "조정금"이라는 이름은 삭제된 `RebalanceTable`이 쓰던 "조정 금액"을 그대로 되살린 것이다. **조정금은 위 %p 차이와 성격이 다르다고 판단해 색 처리를 분리했다** — %p 차이는 "지금 얼마나 벗어났는가"라는 상태값이라 `diffColor`(부호별 색, 상승=빨강/하락=파랑)를 쓰지만, 조정금은 "그래서 얼마를 사고팔아야 하는가"라는 행동값이라 부호는 `+`/`-` 문자로만 나타내고 색은 항상 하나로 고정한다. 처음엔 `text-primary`(딸기, 빨강 계열)를 썼다가 — 그러면 `diff-rise`/`LOSS_COLOR`와 같은 빨강 계열이라 "차이"의 상승 신호와 헷갈릴 수 있다는 지적을 받아 **완전히 다른 색 계열인 `flavor-mango`(호박/amber)로 바꿨다** — 브랜드 팔레트 중 아직 다른 신호로 안 쓰이던 색(민트=`GOOD_COLOR`, 딸기=액센트, 빨강/파랑=`diff-rise`/`diff-fall`)이라 새 의미를 얹어도 충돌이 없다.
- **"유지/매수 필요/매도 필요" 판정 배지와 그 기준(`REBALANCE_THRESHOLD`, 10%p)은 이번에 스펙아웃한다.** 차이의 부호(diffColor)만으로 매수/매도 방향을 나타내고, "조치가 필요한 수준인지"를 가르는 임계값 판정은 만들지 않는다 — 필요해지면 나중에 다시 논의.
- **`/rebalance`, `RebalanceTable`, `RebalanceSummaryCard`, `actionColor`, `actionLabel`, `REBALANCE_THRESHOLD`를 전부 삭제한다.** 흔적만 남기지 않고 통째로 없앤다 — 필요하면 git 기록에서 되살릴 수 있다. `useRebalanceData`/`computeRebalance`/`diffColor`/`GroupCalc.actionAmount`처럼 다른 화면(`/holdings` 등)도 쓰는 계산 로직은 그대로 둔다.

## Consequences
- 내비게이션이 4개에서 3개(포트폴리오/보유 종목/매매일지)로 줄었다.
- 리밸런싱 확인이 별도 페이지 이동 없이 포트폴리오 화면 하나로 끝난다.
- "유지/매수 필요/매도 필요" 판정과 그 설명 팝오버가 없어졌다 — 필요하면 재도입해야 한다(PRD "열린 질문"에 기록). `--diff-rise-strong`/`--diff-fall-strong` CSS 변수는 이제 아무 데서도 안 쓰이지만 `styles/globals.css`에는 남겨뒀다.
- `GroupCalc.actionAmount`의 기존 문서 주석이 매수/매도 부호를 반대로 설명하고 있던 걸 이번에 발견해 고쳤다 — 지금까지는 항상 절댓값만 표시해서 드러나지 않았던 버그였다(실제 계산은 처음부터 맞았다).
- `/portfolio`의 자산군 카드가 정보 밀도가 조금 높아졌다 — 접힌 줄에 3개 값(목표/실제/차이)이 새로 추가됐다. 모바일에서 줄바꿈이 늘 수 있다.
