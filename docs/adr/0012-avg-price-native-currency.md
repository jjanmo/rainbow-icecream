# ADR-0012: 평균매입가는 보유 종목의 원래 통화(국내=KRW, 해외=USD)로 입력·저장

## Status
Accepted

## Context
`avgPrice`가 지금까지 항상 KRW로 저장된다는 규칙이었는데, 해외 종목을 매수한 사용자는 실제로 USD 금액만 알고 있다. 매입 시점의 환율로 직접 환산해서 입력하라고 요구하는 건 번거롭고, 어떤 환율을 써야 하는지도 모호하다(오늘 환율? 매입일 환율?).

## Decision
`avgPrice`의 통화를 홀딩의 `region`으로 결정한다 — 국내는 KRW, 해외는 USD. 별도의 통화 선택 필드를 추가하지 않고 이미 필수값인 `region`을 그대로 활용한다. 종목 추가/수정 모달의 라벨이 `region` 선택에 따라 "평균매입가 (KRW)"/"평균매입가 (USD)"로 동적으로 바뀐다. `computeRebalance`는 라이브 시세가 없을 때의 폴백 통화도 하드코딩된 KRW 대신 이 `region` 기반 통화를 쓰고, 수익률(`returnPct`)은 KRW로 환산된 `priceKrw`가 아니라 같은 통화끼리 비교하는 `priceNative` 기준으로 계산한다.

## Consequences
- 해외 종목의 수익률은 이제 순수 종목 자체의 등락만 반영한다(매입 시점 이후 환율 변동은 섞이지 않음) — 이전보다 더 정확한 "종목 수익률" 정의로 바뀌었다.
- 기존에 "항상 KRW"라는 규칙으로 입력됐던 해외 종목의 `avg_price` 값은 재해석이 필요하다. 테스트 시드 데이터(AAPL/NVDA)는 Supabase에서 직접 보정했다.
- `region`을 잘못 선택해서 등록한 종목은 평균매입가 통화도 함께 잘못 해석된다 — `region` 자체가 신뢰할 수 있는 입력이라는 전제에 의존한다.
