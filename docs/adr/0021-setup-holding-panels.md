# ADR-0021: 설정 페이지 종목 표시 — 읽기 모드 2컬럼 파이차트+리스트, 편집 모드 접힌 줄 요약

## Status
Accepted

## Context
ADR-0018에서 설정 페이지의 종목 행은 티커/종목명만 보여주는 것으로 단순화됐다. 그런데 이후 "그룹 안에서 이 종목이 실제로 얼마나 차지하는지"와 "종목의 실제 데이터(구분/계좌/수량/매입가/평가금)를 한눈에 보고 싶다"는 요구가 다시 나왔다 — 다만 이번엔 편집 가능한 숫자가 아니라 **보여주기 전용** 정보로.

## Decision
- **읽기 모드** (`GroupCard`): 자산군을 펼치면 좌(40%):우(60%) 2컬럼으로 바뀐다. 왼쪽은 그 자산군 안에서 각 종목이 실제 시가 기준으로 차지하는 비중(`HoldingCalc.actualPctInGroup`)을 보여주는 도넛 차트, 오른쪽은 티커/종목명/계좌/평가금을 나열한 리스트(`GroupHoldingsPanel`, 신규). 리스트 항목에 마우스를 올리면 도넛의 해당 조각이 하이라이트된다. 도넛/리스트 색은 `HoldingCalc.color`(그룹 hue의 톤 변형, 다른 화면들이 공유)를 쓰지 않고 이 패널 안에서만 독립적으로 `hueForGroupIndex`를 재사용해 종목마다 뚜렷이 구분되는 색을 새로 배정한다 — 이 패널은 한 그룹 내부만 보여주는 자기완결적 뷰라 그룹 색과 맞출 이유가 없고, 톤 변형만으로는 종목이 많을 때 구분이 잘 안 됐기 때문.
- **편집 모드** (`EditHoldingInlineRow`): 종목 자체의 아코디언이 접혀 있을 때, 오른쪽에 구분·계좌·보유수량·평균매입가·평가금을 한 줄 요약으로 보여준다. 아코디언을 펼치면 이 요약 대신 전체 편집 폼이 나타나고, 다시 접으면 요약이 최신 draft 값으로 갱신된 채 보인다 — 별도의 "저장 시점"이 있는 게 아니라, 각 필드가 이미 blur 시점에 draft에 반영되므로(ADR-0015) 접힌 요약은 그 draft를 그대로 읽어서 보여줄 뿐이다.
- **평가금 계산**: draft 종목은 `computeRebalance`를 거치지 않아 평가금이 없었다. `lib/calc/rebalance.ts`에 `resolveHoldingValueKrw()`를 뽑아내 `computeRebalance` 내부와 draft 양쪽에서 공유하고, `useRebalanceData()`가 `prices`/`usdKrwRate`를 추가로 반환하도록 확장해 `EditGroupCard`가 각 draft 종목의 평가금을 실시간으로 계산해서 내려준다.

## Consequences
- 종목 하나의 "실제로 얼마인지"를 알기 위해 항상 종목 아코디언을 펼칠 필요가 없어졌다 — 읽기 모드는 리스트에서, 편집 모드는 접힌 줄에서 바로 보인다.
- draft 종목의 평가금은 실시간 시세 기준이라, 새로 추가한 종목(아직 저장 안 된)도 실제 시세가 있으면 정확한 평가금이 뜬다. 다만 그 종목의 티커가 서버에 저장된 종목 목록에 아직 없으므로 `useLivePrices`가 폴링하는 티커 목록에는 포함되지 않아, 새 종목은 평균매입가 폴백 값으로만 계산된다 — "완료"로 저장한 뒤 다음 폴링부터 실시간 시세가 붙는다.
- `lib/calc/rebalance.ts`의 가격 해석 로직이 한 곳(`resolveHoldingValueKrw`)으로 모여서, `computeRebalance`와 설정 페이지 draft 계산이 어긋날 위험이 줄었다.
