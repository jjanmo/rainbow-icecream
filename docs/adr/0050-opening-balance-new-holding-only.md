# ADR-0050: 기초잔고는 "+ 새 종목" 전용, 새 종목은 항상 매수로 고정, 새 종목 흐름에 자산종류 추가

## Status
Accepted — ADR-0048이 "기초잔고 체크박스는 새 종목/기존 종목 어느 흐름에서든 쓸 수 있어야 한다"고 정한 부분을 뒤집는다.

## Context

ADR-0048에서 기초잔고 체크박스를 폼 최상단으로 옮기면서, 이미 등록해 둔 기존 종목에도 뒤늦게 기초잔고를 채울 수 있게 만들었다 — "종목 메타데이터만 먼저 등록해두고 나중에 기초잔고를 채우는 경우도 있을 것"이라는 가정이었다. 하지만 실제로 기초잔고는 "이 종목을 매매일지 밖에서 이미 갖고 있었다"는 뜻이고, 그건 그 종목을 매매일지에 **처음** 등록하는 순간에만 의미가 있는 정보다. 이미 매매일지에 체결이 하나라도 있는 기존 종목에 새삼 "사실 이건 기초잔고였다"를 붙이는 상황은 실제로 없다.

또한 새 종목은 정의상 아직 하나도 갖고 있지 않은 것이라 팔 수 없는데도, 폼은 매수/매도 토글을 그대로 보여줘 혼란을 줬다.

## Decision

**기초잔고 체크박스는 "+ 새 종목" 흐름에서만 보인다.** 기존 종목을 고르는 화면(매수·매도 모두)에는 더 이상 나타나지 않는다 — 종목당 기초잔고가 최대 1건이라는 제약과 충돌할 일 자체가 없어지므로, ADR-0048이 도입한 "이미 기초잔고가 있으면 체크박스를 비활성화" 로직도 함께 걷어냈다(새 종목은 정의상 기존 체결이 없다).

**새 종목은 매매 구분이 항상 매수로 고정된다.** "+ 새 종목"으로 전환하면 매매 구분을 매수로 고정하고 토글 자체를 숨긴다(수정 모드처럼 고정 라벨만 보여준다) — 기존 종목 선택 화면에서 매도로 전환하면 자동으로 "+ 새 종목" 상태가 풀리던 기존 동작과 대칭이다.

**매매일지의 "+ 새 종목" 흐름에 자산종류 입력을 추가한다.** ADR-0047은 "새 종목 흐름은 자산종류를 안 물어보고 기본값 ETF로 만든 뒤 보유종목 화면에서 나중에 고치게 한다"고 정했는데, 이번에 정석적인 필드 세트를 요청받으며 그 판단을 뒤집었다 — `HoldingFormDialog`와 같은 `AssetType`/`ASSET_TYPE_LABELS`를 그대로 재사용한다(별도 "?" 도움말 팝오버는 이 폼에서는 생략 — 이미 화면이 조밀해 확인해야 할 필드가 많아, 필요하면 나중에 보유종목 화면에서 설명을 다시 볼 수 있다).

**"+ 새 종목" 필드를 자산군/자산종류, 지역/계좌, 코드(티커)/종목명 3줄 세트로 묶는다.** 점선 박스 안에 이 세 줄만 남기고, 기초잔고 체크박스와 현금성 자산(원화/달러) 체크박스는 박스 밖으로 뺐다 — 전자는 수량/단가 앞에, 후자는 수량/단가(또는 그 대신 나오는 금액 입력) 뒤에 둔다. 현금성 자산 체크박스는 여전히 그 위 금액 입력의 모양(수량+단가 쌍 vs. 금액 하나)을 그대로 바꾼다 — 위치만 아래로 옮겼을 뿐 동작은 같다.

**기초잔고 목록의 열도 정리했다.** 기초잔고는 매매일 자체가 없고(ADR-0048) 매도된 적도 없는 시작점이라 "날짜"·"실현손익" 열이 항상 비어 보였다 — `ExecutionsTable`에 `showDateColumn`/`showRealizedPnlColumn` prop을 추가해 기초잔고 목록 다이얼로그에서만 끈다. (다이얼로그 자체의 `max-h-[85vh] overflow-y-auto`는 그대로 둔다 — 없애면 종목이 많을 때 뷰포트를 넘쳐버린다. 스크롤바만 `scrollbar-hidden`으로 숨긴다.)

**행별 "기초잔고" 배지를 완전히 없앴다.** 이 배지(`OpeningBalanceBadge`)는 원래 캘린더에 기초잔고가 실제 매매와 섞여 보이던 시절(ADR-0044) 구분용으로 만들었는데, ADR-0048이 캘린더에서 기초잔고를 아예 뺀 뒤로는 메인 목록에 기초잔고 행이 나타날 일 자체가 없어져 죽은 코드가 됐다 — "기초잔고 보기" 목록에서도 행 전부가 기초잔고라 반복이라는 이유로 꺼두고 있었다(`showOpeningBalanceBadge={false}`). 즉 두 호출부 어느 쪽도 실제로 배지를 그린 적이 없었다. 배지 컴포넌트·`showOpeningBalanceBadge` prop·관련 JSX를 전부 지우고, 다이얼로그 제목 옆의 "?" 트리거(`OpeningBalanceHelp`, `HoldingFormDialog`의 `AssetTypeHelp`와 같은 모양)만 남겼다 — 파일도 `OpeningBalanceBadge.tsx` → `OpeningBalanceHelp.tsx`로 이름을 맞춰 바꿨다.

## Consequences

- **되돌린 트레이드오프**: 이미 `/holdings`에서 메타데이터만 등록해 둔(수량 0인) 기존 종목에 나중에 기초잔고를 소급 등록할 UI 경로가 없어졌다. 그 종목이 매도 시 수량 부족 오류를 내면, 지금은 일반 매수 체결(오늘 날짜의 `NEW`)로 수량을 채우는 것 말고는 방법이 없다 — 매매 횟수 집계에 실제 매매가 아닌 기록이 하나 섞인다는 뜻이다. 실사용에서 이 경로가 자주 필요해지면 재검토할 부분으로 남겨둔다.
- `NewHoldingDraft`(폼 내부 상태)에 `assetType: AssetType` 필드가 생겼고, `ExecutionFormDialog`가 새로 만드는 `NewHolding` 객체는 더 이상 `assetType: 'ETF'`를 하드코딩하지 않는다.
- `docs/PRD.md`도 갱신했다.
