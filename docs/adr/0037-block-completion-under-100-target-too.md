# ADR-0037: 자산군 목표 비중 합계가 100% 미만이어도 완료를 막는다

## Status
Accepted (ADR-0016의 "100% 미만은 막지 않는다" 부분을 대체)

## Context

ADR-0016은 목표 비중 합계가 100%를 **초과**하면 완료를 막되, **미만**은 "아직 다 정하지
않은 정상적인 중간 상태"로 보고 저장을 허용했다. 하지만 실제로는 미완성 상태를 그대로
저장해두면 다른 화면(비중 체크 등)에서 판단 기준 자체가 어긋난 채로 굳어질 수 있고,
사용자도 "일단 저장해두고 나중에 마저 정하기"보다는 그 자리에서 100%를 맞춰서 완료하는
쪽을 원한다는 게 확인됐다 — 미만도 초과와 마찬가지로 완료를 막아달라는 요청.

## Decision

- 편집 모드의 `draftTargetSumInvalid`(`pages/setup.tsx`)는 이제 초과(`> 100`)뿐 아니라
  미만도 함께 잡는다: `Math.abs(draftTargetSum - 100) >= 0.5`. 허용 오차 0.5%p는 읽기
  모드의 `targetSumOk`(`Math.abs(data.targetSum - 100) < 0.5`)와 동일한 기준을 그대로
  재사용해, 편집 중 판정과 저장된 값에 대한 판정이 어긋나지 않게 했다.
- "완료" 버튼은 `draftTargetSumInvalid`일 때 비활성화되고, 초과/미만 어느 쪽이든 경고
  문구가 버튼 아래 노출된다 — 문구는 읽기 모드 배지와 같은 어투("100%보다 X% 초과" /
  "100%까지 X% 부족")를 쓴다.

## Consequences
- 목표 비중 합계가 정확히 100%(오차 0.5%p 이내)가 아니면 편집을 완료할 수 없다 — 자산군
  배분을 일부만 정한 중간 상태를 서버에 저장해두고 나중에 이어가는 흐름은 더 이상 지원하지
  않는다. 편집을 시작했다면 그 세션 안에서 100%를 맞추거나, "취소"로 되돌려야 한다.
- 읽기 모드의 `targetSumOk` 배지는 그대로 유지된다 — 편집 중이 아닌 상태에서 이미 저장된
  값이 (드물게) 100%를 벗어나 있는 경우를 계속 알려준다.
