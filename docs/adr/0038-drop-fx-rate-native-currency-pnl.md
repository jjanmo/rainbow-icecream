# ADR-0038: 체결에 환율을 저장하지 않는다 — 실현손익은 거래 통화 기준으로만 표시한다

## Status
Accepted (ADR-0029를 대체)

## Context

ADR-0029는 해외 종목 체결마다 환율을 입력받아 고정 저장했다 — 원화 환산 실현손익을
과거 시점 값으로 안정시키고, 주가 손익과 환차손익을 분해해서 보여주려는 목적이었다.

그런데 실제로 써보니 이 필드가 혼란스러웠다: "환율 (USD→KRW) · 체결 시점 값으로 고정
저장"이라는 문구는 "그 날짜의 실제 환율을 자동으로 알아낸다"처럼 읽히지만, 실제로는
그냥 폼을 여는 **지금 이 순간의 실시간 환율**이 기본값으로 채워질 뿐이었다(과거 날짜로
체결일시를 입력해도 환율 기본값은 바뀌지 않는다 — Toss 연동은 스팟 조회만 지원하고
과거 날짜 조회를 지원하지 않는다). 사용자가 직접 정확한 값으로 고치지 않으면 사실상
의미 없는 숫자가 저장되는 구조였다.

더 근본적으로: 해외 종목은 애초에 달러로 사고 달러로 판다. 실현손익(매도가-평단가)은
환율 없이 달러만으로 이미 정확하고 완결된 숫자다. 원화로 환산해야만 알 수 있는 값이
아니다. 그리고 ADR-0029가 이 필드를 만든 목적이었던 "환차손익 분해" 기능은 실제로는
`replay.ts` 안에만 존재했고, 매매일지 화면 어디에도 노출된 적이 없었다 — 만들어진
적 없는 기능을 위해 매 체결마다 애매한 입력을 요구하고 있었던 셈이다.

## Decision

- `executions.fx_rate` 컬럼과 `Execution.fxRate` 필드를 없앤다. 체결 입력 폼에서
  환율 입력 자체가 사라진다.
- 실현손익(`ClosedLot.realizedPnl`, `ReplayResult.totalCost`)은 **거래 통화 기준으로만**
  계산·표시한다 — 해외 종목은 달러, 국내 종목은 원화. 원화 환산은 하지 않는다.
  `ClosedLot.realizedPnlKrw`/`ReplayResult.totalCostKrw`(환차손익 분해용)도 함께 없앤다.
- 매매일지 체결 목록에 실현손익을 처음으로 노출한다 — 매도 건마다 그 종목의 전체
  체결 이력을 리플레이해서 얻은 `realizedPnl`을 거래 통화로 보여준다(`pages/journal.tsx`의
  `closedLotByExecutionId`). 지금까지 이 값을 실제로 보여주는 화면이 없었다.
- **평가금액(보유 중인 종목의 원화 환산)은 이 결정과 무관하다** — `useExchangeRate`의
  실시간 환율을 그대로 쓴다. ADR-0029가 세운 "실시간 환율은 평가금액에만, 실현손익에는
  쓰지 않는다"는 경계는 그대로 유지된다. 이번 결정은 그 경계의 "실현손익" 쪽을 아예
  "환율 자체를 쓰지 않는다"로 더 단순화한 것이다.

## Consequences

- 체결 입력 폼에서 필드 하나(환율)가 완전히 사라진다 — 해외 종목 매매 기록이 더 빨라지고,
  "이 값을 뭘 넣어야 하나" 하는 혼란이 없어진다.
- 실현손익이 항상 정확하고 이해하기 쉽다 — 달러로 사서 달러로 판 결과를 달러로 보여줄
  뿐이라, 환율 데이터 품질(사용자가 대충 입력했는지)에 좌우되지 않는다.
- **잃는 것**: 환차손익을 원화 기준으로 분해해서 보는 기능은 없다. "달러로는 손해인데
  원화로는 이득"인 상황을 이 앱이 숫자로 보여주지는 않는다 — 사용자가 원화가 궁금하면
  실현손익(달러)에 오늘 환율을 곱해 어림잡아야 한다(다만 이건 매번 오늘 환율에 따라
  달라지는 참고용 계산일 뿐, 이 앱이 저장·추적하는 값은 아니다).
- 스키마가 단순해진다 — `executions`에 통화 관련 컬럼이 하나도 남지 않는다(가격은 이미
  거래 통화 기준으로만 저장된다).

## 대안

- **필드는 유지하고 문구만 명확히 한다**("지금 환율이 기본값이며 실제 적용받은 값으로
  고쳐야 정확합니다"): 혼란의 근본 원인(입력 자체의 필요성)을 해소하지 못하고, 쓰이지도
  않는 환차손익 분해 기능을 위해 계속 입력을 요구하게 된다. 기각.
- **항상 조회 시점 환율로 환산**: ADR-0029가 이미 검토 후 기각한 방식과 같다 — 과거
  실현손익이 매일 바뀌어 "실현"이라는 말의 의미가 없어진다. 기각.
