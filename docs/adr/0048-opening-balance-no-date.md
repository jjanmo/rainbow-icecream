# ADR-0048: 기초잔고는 날짜 없이 기록, 매매일지 캘린더에서 제외

## Status
Partially superseded by [ADR-0050](./0050-opening-balance-new-holding-only.md) — "기초잔고 체크박스를 새 종목/기존 종목 어느 흐름에서든 쓸 수 있게 한다"는 부분이 뒤집혔다(이제 "+ 새 종목" 전용). 날짜 없이 기록하고 캘린더에서 제외한다는 핵심 결정은 그대로다. 이 ADR 자체는 ADR-0044가 도입한 "기초잔고를 캘린더에 그대로 보여준다"를 뒤집는다.

## Context

ADR-0044는 기초잔고(intent='OPENING_BALANCE') 체결도 다른 체결과 똑같이 체결일시를 입력받아 캘린더에 그대로 보여주기로 했다 — 예전엔 숨겼는데, 숨기면 나중에 고칠 방법이 없어졌기 때문이다.

하지만 기초잔고는 애초에 "매매일"이라는 게 없는 개념이다. 매매일지를 쓰기 시작하기 전부터 갖고 있던 잔고를 기록하는 것이라, 사용자가 실제로 산 날짜를 모르거나 의미가 없는 경우가 대부분이다. 그런데도 폼은 날짜를 필수로 요구했고, 사용자는 아무 날짜나 지어내야 했다. 지어낸 날짜가 캘린더 특정 칸에 찍히는 것도 부자연스럽다 — 실제로 그날 아무 매매도 없었는데 배지가 뜬다.

## Decision

**`executions.executed_at`을 nullable로 바꾼다.** 실제 매매(`intent='NEW'`)는 여전히 필수이고, 기초잔고만 예외다 — 테이블 제약(`executions_executed_at_required_for_trade`, `check (intent = 'OPENING_BALANCE' or executed_at is not null)`)으로 강제한다. 기존에 기초잔고 행에 남아있던 날짜도 마이그레이션으로 비워서, "기초잔고는 날짜가 없다"를 예외 없는 불변식으로 만들었다.

**리플레이 정렬은 intent 우선으로 바꾼다.** `replayHolding`이 체결을 시간순으로 재생하는데, 날짜가 없는 기초잔고를 날짜로 정렬할 수 없다. 종목당 기초잔고는 최대 1건(유니크 인덱스)이므로, "기초잔고가 있으면 무조건 맨 앞, 나머지는 실제 매매끼리 날짜순"으로 바꾸면 된다 — 원래도 기초잔고가 그 종목의 가장 이른 상태를 나타내므로 의미상 달라지는 게 없다.

**캘린더/월별·일별 목록에서 뺀다.** 날짜가 없으니 애초에 특정 날짜 칸에 넣을 수 없다 — `executionsByDay`를 만들 때 기초잔고를 걸러낸다. 대신 매매일지 화면에 "기초잔고 보기" 버튼을 두고, 클릭하면 기초잔고만 모아 보여주는 목록(같은 `ExecutionsTable` 컴포넌트 재사용, 정렬/수정/삭제 그대로 지원)을 연다 — 수정·삭제 경로는 잃지 않는다(ADR-0049).

**입력 폼도 바꾼다.** 기초잔고 체크박스를 폼 최상단으로 옮기고(예전엔 "+ 새 종목" 흐름 안에만 있었다), 새 종목/기존 종목 어느 쪽을 고르든 쓸 수 있게 했다 — 이미 등록해 둔 종목에 뒤늦게 기초잔고를 채우는 경우도 있기 때문이다. 체크하면 체결일시 입력 자체가 사라지고, 매매 구분도 항상 매수로 고정된다(기초잔고는 개념상 "보유"라 매도 방향이 없다). 종목에 이미 기초잔고가 있으면(유니크 제약) 체크박스를 비활성화하고 이유를 보여준다.

## Consequences

- `Execution.executedAt`, DB `executions.executed_at` 모두 `string | null`이 됐다 — 이 필드를 읽는 모든 곳(`replayHolding`, `ExecutionsTable`, `ExecutionFormDialog`의 매수 메모 이력 등)이 null을 방어적으로 다뤄야 한다. 다만 실제 매매(SELL 포함)는 DB 제약상 항상 날짜가 있으므로, "매도 체결의 날짜"처럼 개념상 항상 있는 값까지 옵셔널 체이닝을 남발할 필요는 없다 — `replay.ts`가 SELL 분기 진입 시 한 번만 단언한다.
- 기초잔고 배지(`OpeningBalanceBadge`)와 "기초잔고 보기" 목록은 유지된다 — 다만 목록의 "날짜" 열은 기초잔고 행에서 항상 대시(—)로 보인다.
- `docs/PRD.md`도 갱신했다.
