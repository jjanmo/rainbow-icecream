# ADR-0025: 종목 색상은 최초 생성 순서에 고정

## Status
Accepted

## Context

종목의 색은 자산군 hue의 tint로 파생되며(`tintForIndex`), 그 밝기 단계는 자산군 안에서의 인덱스로 결정된다. 이 인덱스를 **표시 순서**(`sort_order`, ADR-0015의 드래그 재정렬 결과)에서 뽑고 있었기 때문에, 종목을 드래그해서 순서를 바꾸면 그 종목뿐 아니라 사이에 끼인 다른 종목들의 색까지 함께 이동했다.

"위에서부터 진한 색 → 아래로 옅은 색" 그라데이션이 항상 유지되는 건 목록 자체로는 깔끔하지만, 색이 종목을 식별하는 단서로는 쓸 수 없게 된다 — 설정 페이지에서 순서를 한 번 바꾸면 사용자가 기억하던 색-종목 연결이 끊어진다.

## Decision

색상 인덱스를 **표시 순서와 분리**한다. 표시 순서는 계속 `sort_order` → `created_at` → `id`를 따르되, 색상 인덱스는 자산군 안에서 `created_at` → `id`(=최초 생성 순서)만으로 계산한다.

`computeRebalance`가 두 순서를 각각 만든다:
- `holdingsStable` — 표시 순서 (`byOrderThenCreatedThenId`)
- `colorSlotById` — 색상 슬롯 (`byCreatedThenId`, 그룹별로 0..n-1)

설정 페이지 편집 모드도 같은 규칙을 따라야 하므로(안 그러면 편집 중과 저장 후의 색이 달라진다) `DraftHolding`이 `createdAt`을 함께 들고 오고, `draftColorSlots`가 같은 순서로 슬롯을 계산한다. 편집 중 새로 추가한 종목은 아직 `created_at`이 없으므로 맨 뒤에 놓인다 — 저장 후 실제로 갖게 될 위치와 같다.

## Consequences

- 종목의 색이 생성 시점에 정해져 평생 유지된다. 드래그 재정렬로 색이 바뀌지 않으므로 설정/비중 체크/보유 종목 페이지에서 같은 종목이 항상 같은 색으로 보인다.
- 목록의 색이 위→아래 진하기 순으로 정렬되어 보이지는 않는다. 재정렬하면 색 순서가 섞인 채로 남는다 — 색을 정렬 신호가 아니라 식별 신호로 쓰기로 한 대가다.
- 한 번의 편집 세션에서 같은 자산군에 종목을 2개 이상 새로 추가하면, 그것들끼리의 색 순서는 저장 직후 한 번 바뀔 수 있다(저장 전에는 `created_at`이 없어 clientKey로 타이브레이크하므로). 기존 종목의 색에는 영향이 없다.
- 그룹 안에서 종목을 삭제하면 남은 종목들의 `total`이 줄어들어 tint 간격이 다시 벌어진다(색이 조금 바뀐다). 생성 순서 자체는 유지되므로 순서가 뒤바뀌지는 않는다.
- 자산군 자체의 색은 여전히 위치 파생(ADR-0019)이라 자산군을 재정렬하면 그룹 색과 그 안의 종목 색조가 함께 바뀐다 — 이건 의도된 동작으로 유지한다.
