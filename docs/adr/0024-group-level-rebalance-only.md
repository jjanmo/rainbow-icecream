# ADR-0024: 리밸런싱 판단은 자산군 단위로만

## Status
Accepted

## Context

ADR-0018에서 "종목이 자산군 내에서 차지할 목표 비중"(`target_pct_in_group`)을 직접 설정하는 UI를 제거했다 — 그 값을 사용자가 손으로 정하는 게 실질적으로 무의미하다고 판단했기 때문이다.

그런데 비중 체크 페이지의 계산은 그대로 남아 있었다:

- 종목의 전체 목표 비중 = `자산군 목표% × 그룹내 목표% ÷ 100`
- 종목별 괴리(`diff`) = 실제 비중 − 위 목표 비중
- 그 괴리로 종목별 "매도 필요 / 매수 필요 / 유지"를 판정

입력 경로가 사라진 뒤로 `target_pct_in_group`은 신규 종목에서 항상 0이 되므로, 종목의 전체 목표 비중도 항상 0%가 된다. 즉 종목별 판정은 **아무도 설정하지 않은 숫자와 비교하는 판정**이 되어, 보유 비중이 조금이라도 큰 종목은 무조건 "매도 필요"로 뜬다. 목표를 자산군 단위로만 정하는 지금의 제품에서는 종목 단위 매수/매도 알림 자체가 성립하지 않는다.

## Decision

리밸런싱 판단(괴리, 조치 필요 여부, 조치 필요액)은 **자산군 단위로만** 수행한다.

- `GroupCalc`가 `diff`와 `actionAmount`(양수=매도, 음수=매수)를 가진다.
- `HoldingCalc`에서 종목 단위 목표/괴리/조치 필요액(`targetPct`, `diff`, `actionAmount`)을 제거한다. 종목에 남는 지표는 실제 비중(`actualPct`, `actualPctInGroup`)과 수익률뿐 — 전부 "목표 없이도 성립하는" 값이다.
- 비중 체크 페이지는 자산군 요약 카드 + 자산군 테이블 두 블록으로 구성한다. 종목 단위 목표 비중 진행바(`GroupProgressBar`/`HoldingProgressBar`/`MiniBar`)는 제거한다.
- `REBALANCE_THRESHOLD`(5%p)는 자산군 괴리에만 적용된다.

DB의 `holdings.target_pct_in_group` 컬럼과 도메인 타입/CRUD/draft 필드는 **남겨둔다.** 비중 체크 로직을 앞으로 다시 손볼 예정이므로, 종목 단위 목표 개념을 어떤 형태로든 되살릴 여지를 없애지 않는다. 다만 현재는 화면 어디에서도 읽지 않는 값이라는 점을 분명히 해둔다 — 설정 페이지 아코디언이 보여주는 "자산군 내 비중"은 현재 시세 기준 **실제** 비중(`actualPctInGroup`)이며 이 컬럼과 무관하다.

## Consequences

- 종목별로 "얼마 사고 팔아야 하는지"는 더 이상 알려주지 않는다. 자산군 단위 조치 금액만 나오므로, 그 금액을 그룹 내 어느 종목에 배분할지는 사용자 판단에 맡긴다.
- 설정하지 않은 목표와 비교해 잘못된 매도/매수 신호를 내보내는 문제가 사라진다.
- `target_pct_in_group`은 저장은 되지만 읽히지 않는 컬럼으로 남는다 — 계산에 다시 쓰려면 입력 경로부터 되살려야 한다는 뜻이며, 그 판단은 비중 체크 로직 개편 때 함께 한다.
