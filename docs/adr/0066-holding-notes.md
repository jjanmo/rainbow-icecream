# ADR-0066: 종목 단위 메모(holding_notes) — 날짜별 근거와 나란히

## Status

Accepted — ADR-0043이 Consequences에 남긴 "종목 단위 노트가 필요해지면 새 테이블을 다시 만든다"를 실행한다.

## Context

근거 테이블을 따로 둔 의도는 두 가지였다.

1. 매매할 때 적은 근거는 **그 날짜(체결)와 함께** 남긴다 — 지금의 `trade_notes`(체결 하나당 하나, ADR-0043).
2. 날짜·매매와 상관없이 **종목 자체에 대한 생각·포인트**를 매수/매도 쪽으로 정리한다 — 이게 없었다.

"날짜별 근거를 하나의 텍스트 칸으로 합쳐 함께 고치자"는 요청에서 출발했지만, 체결별 근거를 텍스트 하나로
합치면(파싱으로 되돌려 저장) 날짜 줄을 고치는 순간 어느 체결 근거인지 깨지고, 근거를 종목 단위 하나로
**대체**하면 1번(자동 날짜)이 사라진다. 그래서 대체가 아니라 **추가**로 간다.

## Decision

- **새 테이블 `holding_notes`**(`user_id, identity_key` 유니크, `buy_memo`, `sell_memo`) — 자유 서술,
  어떤 집계에도 쓰지 않는다(`trade_notes.body`와 같은 원칙).
- **holding 행이 아니라 `identity_key`(티커+지역, 현금성은 이름+지역)에 붙인다** — 전량 매도하면
  holding 행은 소프트 삭제되고(ADR-0054) 재매수는 새 행을 만들므로, `holding_id`에 붙이면 메모가 새 행과
  이어지지 않는다. 키는 매매일지 종목 모드가 이력을 묶는 `holdingIdentityKey`(`lib/journal/holdingIdentity.ts`)와
  같다 — 키 형식을 바꾸면 기존 메모가 끊긴다.
- **종목 모드 매수/매도 근거 칸**: 위는 날짜별 근거(체결마다, **내용 있는 것만** — 빈 체결도 보이게 했던 것을
  되돌렸다), 아래는 "내 생각 · 종목 포인트" 칸(매수 칸·매도 칸에 하나씩, 수정 → 저장). 저장은 그쪽 칸만
  upsert하고 다른 쪽은 건드리지 않는다. 빈 값은 null.
- **매도할 때 매매 모달**: 기존 "매수 메모 이력" 위에 그 종목의 매수 쪽 메모도 보여준다 — 매수 근거를 다시 보고
  팔게 하는 기존 장치와 같은 목적.
- 날짜별 근거를 메모 칸으로 옮겨 주는 "불러오기"는 두지 않는다 — 같은 내용이 두 번 보이고 복사본이 따로 놀게 되며,
  메모 칸은 날짜와 무관한 생각을 위한 곳이라 역할이 다시 섞인다. 필요해지면 그때 붙인다.

## Consequences

- 근거가 두 층이 된다: 날짜별(체결) / 종목 단위(메모). 어느 쪽에 적을지는 사용자 몫이다.
- 날짜별 근거가 없는 체결에 근거를 새로 다는 건 다시 체결 수정 모달에서만 된다(종목 모드에서는 내용 있는
  근거만 보이므로).
- 같은 종목을 여러 계좌에서 들고 있어도 메모는 종목(티커+지역)당 하나다.
