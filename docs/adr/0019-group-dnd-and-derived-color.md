# ADR-0019: 자산군 드래그 재정렬 + 위치 기반 자동 색상 (수동 색상 설정 제거)

## Status
Accepted

## Context
종목은 이미 드래그로 순서를 바꿀 수 있는데(ADR-0015) 자산군은 그럴 수 없었다. 또한 자산군 색상은 6개의 고정 "flavor" 팔레트 중에서 사용자가 직접 고르는 방식(`SwatchPicker`, `flavor_index` 컬럼)이었는데, 그룹이 6개를 넘으면 색이 겹치고, 사용자가 매번 수동으로 구분되는 색을 골라야 하는 부담이 있었다.

## Decision
- `holdings`와 동일한 패턴으로 `asset_groups`에 `sort_order` 컬럼을 추가하고(기존 `created_at` 순서로 백필), `flavor_index` 컬럼은 완전히 삭제했다 — 더 이상 색상을 저장하지 않는다.
- 자산군 색상은 이제 **그 자산군이 목록에서 몇 번째인지(순서)와 전체 자산군 개수만으로 계산**한다(`lib/calc/color.ts`의 `hueForGroupIndex(index, total)`) — 색상환을 그룹 개수만큼 균등하게 나눠 배정하므로, 그룹이 몇 개든 항상 서로 최대한 구분되는 색이 나온다. 고정 6색 팔레트보다 더 많은 그룹에서도 안정적으로 구분된다.
- 설정 페이지에서 자산군 카드를 드래그해서 순서를 바꿀 수 있다(`EditGroupCard`에 grip 핸들 추가, 페이지 레벨 `DndContext`/`SortableContext`). 순서가 곧 색상 배정 순서이기도 하다.
- `SwatchPicker` 컴포넌트와 그걸 쓰던 색상 선택 UI를 완전히 제거했다 — 사용자가 자산군 색을 직접 고르는 기능은 더 이상 없다.

## Consequences
- 자산군 색이 항상 자동으로, 항상 서로 구분되게 정해진다 — 사용자가 신경 쓸 필요가 없어졌다.
- 자산군 순서를 바꾸면(드래그하거나 자산군을 추가/삭제하면) 다른 자산군들의 색도 함께 재계산되어 바뀔 수 있다 — 특정 자산군에 "고정된 색"이라는 개념 자체가 없어졌다(의도된 트레이드오프).
- `lib/api/groups.ts`의 정렬(`order("sort_order")`)과 `lib/calc/rebalance.ts`의 그룹 정렬·색상 계산이 같은 순서를 기준으로 삼아야 화면과 저장된 순서가 어긋나지 않는다 — holdings의 `byOrderThenCreatedThenId`를 그대로 재사용해 그룹에도 적용했다.
- 기존에 `flavor_index`로 저장돼 있던 값은 마이그레이션으로 완전히 삭제됐다 — 되돌릴 수 없다.
