# ADR-0061: 자산종류·계좌 옵션 개편

## Status

Accepted

## Context

매매일지("+ 새 종목")·`/holdings` 종목 폼의 자산종류·계좌 드롭다운을 사용해보니 실제로
쓰이지 않는 항목(리츠, CMA, 파킹통장, 예적금)과 라벨 표기(개별 주식/일반 펀드/예수금)를
다듬을 필요가 있었고, 새로 금현물·DC(퇴직연금)를 담을 곳이 없었다.

## Decision

**자산종류(`asset_type`)**를 개별주식/ETF/ETN/펀드/채권/금현물/현금성 7개로 바꾼다.
`AssetType` 값 자체가 바뀌는 항목: `REIT` 제거, `GOLD`(금현물) 추가. 나머지는 라벨만
다듬었다(`STOCK` "개별 주식"→"개별주식", `FUND` "일반 펀드"→"펀드", `CASH` "예수금"→"현금성").
`asset_type`엔 DB CHECK 제약(`holdings_asset_type_check`)이 걸려있어 REIT를 빼려면
기존 REIT 종목을 먼저 재분류해야 했다 — 운영 DB엔 리츠가 개별 상장 종목 형태로
거래되는 **SK리츠(395400) 1건**뿐이라 **개별주식(STOCK)**으로 재분류했다. `GOLD`는
운영 DB에 해당 종목이 없어 데이터 마이그레이션 없이 제약만 넓혔다.

**계좌(`account`)**를 일반계좌/ISA/연금저축/DC/IRP/기타 6개로 바꾼다. `CMA`/`파킹통장`/
`예적금`을 빼고 `DC`를 추가했다. `account`는 CHECK 제약이 없는 자유 텍스트 컬럼이라
스키마 변경은 필요 없었지만, 옵션에서 빠지는 값으로 저장된 기존 종목(카카오뱅크
파킹통장, OO은행 정기예금 — 둘 다 `현금성` 자산)은 드롭다운에서 선택 불가능한
고아 값으로 남으므로 **일반계좌**로 재분류했다(사용자 확인, 2026-09-14). `CMA`로
저장된 종목은 없었다.

## Consequences

- `supabase/schema.sql`의 초기 `create table holdings` CHECK도 새 7개 값으로 갱신하고,
  파일 하단에 기존 DB용 idempotent 마이그레이션 블록(재분류 UPDATE + 제약 재생성)을
  추가했다 — 새로 스키마를 적용하는 환경과 기존 운영 DB가 같은 최종 상태로 수렴한다.
- `account`는 여전히 자유 텍스트라, 화면 드롭다운에 없는 값이 향후 다시 생겨도(예:
  수기 데이터 이관) DB 레벨에서는 막히지 않는다 — 드롭다운 옵션과 실제 저장값이
  어긋날 수 있다는 걸 염두에 둘 것.
- `assetType`은 라벨/정렬에만 쓰이고 리밸런스·exposureRegion 파생 로직은 `region`
  기준이라(`lib/calc/axisRebalance.ts`) 이번 값 변경으로 계산 로직이 깨지는 곳은 없다.
