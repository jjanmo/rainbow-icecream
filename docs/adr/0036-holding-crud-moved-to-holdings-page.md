# ADR-0036: 종목 CRUD를 보유종목 페이지로 일원화하고, 설정 페이지엔 자산군 간 드래그 이동을 추가한다

## Status
Accepted (ADR-0015의 "아코디언 인라인 편집"을 대체)

## Context

지금까지 종목 데이터(티커·구분·계좌·보유수량·평균매입가·비고)를 고치는 경로가 두
군데였다 — 보유종목 페이지의 `HoldingFormDialog`(ADR-0006)와 설정 페이지 편집 모드의
아코디언 인라인 폼(`EditHoldingInlineRow`, ADR-0015). 두 폼은 같은 데이터를 다루면서도
독립적으로 유지보수되다 보니 필드가 벌어지는 일이 실제로 있었다(현금성 자산 체크박스가
한쪽에만 있던 사례 등).

사용자가 페이지 역할을 다시 정리했다: **설정 페이지는 자산군 CRUD와 비중 조회, 종목의
정렬/재배정만 다루고, 종목 데이터 자체의 CRUD는 보유종목 페이지가 전담한다.** 대신
"자산군을 잘못 넣었을 때 페이지를 옮기지 않고 바로잡을 수 있어야 한다"는 요구가 있었다 —
그래서 자산군 간 드래그 이동을 새로 지원한다.

## Decision

**설정 페이지 편집 모드에서 종목 CRUD를 없앤다**:
- `EditGroupCard`의 "+ 종목 추가" 버튼과 그 핸들러를 제거했다. `pages/setup.tsx`의
  `HoldingFormDialog` 인스턴스(추가용)도 함께 없앴다.
- `EditHoldingInlineRow`에서 펼침 편집 폼(자산군/티커/종목명/구분/계좌/수량/평단/비고
  입력)과 삭제(X) 버튼을 없앴다. 지금은 드래그 핸들 + 색 점 + 티커/이름 + 한 줄 요약
  (구분·계좌·수량·평단·평가금)만 있는 읽기 전용 행이다 — 읽기 모드의
  `GroupHoldingsPanel`(ADR-0021)과 결이 비슷해졌다.

**대신 자산군 간 드래그 이동을 추가한다** — 종목을 다른 자산군의 카드 위로 드래그하면
그 자산군으로 옮겨진다(맨 뒤에 추가). 접힌 자산군도 드롭 대상이다(카드 헤더 자체가
`useDroppable`). 이걸 구현하려면 dnd 구조를 바꿔야 했다:
- 기존엔 그룹 재정렬용 `DndContext`(페이지 레벨)와 각 `EditGroupCard`가 자기 종목
  재정렬용으로 따로 갖던 `DndContext`(그룹별로 격리)가 있었다. dnd-kit에서
  `useDraggable`/`useSortable`은 항상 **가장 가까운** `DndContext`에 묶이므로, 두
  `DndContext`를 중첩하면 안쪽에 렌더되는 모든 게(그룹 카드 자신의 드래그 핸들까지)
  안쪽 컨텍스트에 잘못 묶인다.
- 그래서 **`DndContext` 하나만 페이지 레벨에 둔다.** 그룹 카드와 종목 모두 이 하나의
  컨텍스트에서 드래그되고, `useSortable`에 실은 `data.type`(`'group'` vs `'holding'`)으로
  `handleDragEnd`가 어느 쪽 로직을 탈지 가른다. `SortableContext`는 여전히 그룹 목록 하나,
  자산군마다 종목 목록 하나씩 — 이렇게 여러 개를 중첩해도 문제없다(하나의 `DndContext`
  안에서 "어떤 목록들이 서로의 드롭 대상인가"만 결정할 뿐이다). dnd-kit 공식 "Multiple
  Containers" 예제와 같은 구조다.
- `onDragOver`가 종목이 다른 자산군 위로 넘어가는 순간 `groupClientKey`를 낙관적으로
  바꿔서(`moveDraftHoldingToGroup`, `lib/setupDraft.ts`) 드래그 중 미리보기가 실제로
  옮겨진 것처럼 보이게 하고, `onDragEnd`가 최종 자산군 안에서의 정확한 순서를
  `reorderDraftHoldings`로 확정한다.

## Consequences

- 종목 필드는 이제 `HoldingFormDialog` 하나만 유지하면 된다 — 두 폼이 벌어지는 문제가
  구조적으로 사라졌다.
- 설정 페이지에서 종목을 "빠르게 훑어보고 자산군만 바로잡는" 흐름은 유지되지만, 세부
  데이터를 고치려면 보유종목 페이지로 가야 한다.
- `commitSetupDraft`(`lib/setupDraft.ts`)의 종목 add/delete 처리 로직은 그대로 남겨뒀다 —
  지금은 설정 페이지 UI가 그 경로를 타지 않지만(종목 추가/삭제 버튼이 없다),
  범용 diff 함수의 방어 로직을 굳이 걷어낼 이유가 없었다. 실제로 호출되는 건 update(자산군
  재배정·순서 변경)뿐이다.
- `EditGroupCard`는 더 이상 `groupOptions`를 받지 않는다 — 종목의 자산군을 Select로
  고르는 UI가 없어졌기 때문이다.
- 빈 자산군(드래그로 종목을 다 빼낸 경우)엔 안내 문구를 둬서 "여기로 드래그하거나
  보유종목에서 등록하라"고 알린다.
- 브라우저 로그인 자격 증명이 없어 실제 드래그 인터랙션은 코드 리뷰로만 보장했다 —
  사용자가 직접 확인해야 한다.

## 대안

- **모달을 그대로 열되 자산군만 미리 채워서 열기**: 편집 모드 안에서 또 모달이 뜨는
  경험이 ADR-0015가 애초에 피하려던 문제라 기각.
- **종목 필드를 계속 아코디언에 남기고 두 폼을 공유 하위 컴포넌트로 리팩터링**: 드리프트
  재발을 막을 순 있지만, 사용자가 원한 "역할별 CRUD 분리"라는 더 단순한 경계를 얻지
  못한다.
