# ADR-0022: 종목 추가/수정 모달에 원화/달러 체크박스로 현금성 자산 등록 경로 복구

## Status
Partially superseded by [ADR-0044](./0044-holdings-balance-write-only-via-journal.md) — 현금성 자산을 새로 만들거나 금액을 정하는 건 매매일지의 "+ 새 종목" 흐름으로 옮겨갔다. `HoldingFormDialog`는 기존 현금성 종목의 티커 입력을 비활성화해 두는 표시 로직만 남아 있다.

## Context
`lib/calc/rebalance.ts`는 원래부터 `ticker: null`인 종목을 "시세 조회 없이 평균매입가를 그대로 평가금으로 쓰는" 현금성 자산으로 취급해왔다. 하지만 이후 `HoldingFormDialog`가 모든 추가/수정에 비어있지 않은 티커/코드를 요구하도록 바뀌면서, 이 상태를 UI로 만들거나 유지할 방법이 없어졌다 — 기존에 `ticker: null`이던 행만 남아있고, 그 행을 수정하려는 순간 티커 입력을 강제당했다. 예적금·파킹통장처럼 티커가 없는 보유 항목을 다시 등록/수정할 수 있어야 한다는 요청이 있었다.

## Decision
`HoldingFormDialog`의 보유수량/평균매입가 행 아래에 `KRW`/`$` 체크박스 두 개를 추가한다 (서로 배타적, `Checkbox`는 이번에 `shadcn add checkbox`로 새로 도입한 base-nova/Base UI 컴포넌트).
- 체크하면: 해당 통화에 맞는 `region`(KRW→국내, $→해외)을 자동으로 맞추고, 코드/티커 입력 필드를 비활성화한다. 동시에 보유수량+평균매입가 두 필드는 "금액(KRW/USD)" 입력 하나로 바뀐다 — 현금성 자산은 수량 개념이 없고 총액 하나만 의미가 있기 때문이다.
- 제출 시 `ticker`는 강제로 `null`, `qty`는 강제로 `1`, `avgPrice`는 입력한 금액이 된다. 필수값 검증에서도 티커가 제외되고 종목명/계좌/금액만 있으면 등록 가능하다.
- 체크 해제(기본값): 기존과 동일하게 티커/코드 + 보유수량 + 평균매입가가 필수다.
- 기존에 `ticker: null`인 종목을 수정 모달로 열면 저장된 `region` 기준으로 체크박스가 자동 체크되고, 금액 필드는 `qty * avgPrice`(기존 행이 qty=1이 아니었어도 총액은 보존)로 미리 채워진다.

## DB 저장 방식
`holdings` 테이블에는 "금액" 전용 컬럼이 없다 (`supabase/schema.sql`) — `qty numeric`, `avg_price numeric`만 있다. 그래서 금액 입력은 `avg_price` 컬럼에, `qty` 컬럼에는 `1`이 그대로 저장된다. `ticker` 컬럼은 `null`. 평가금 계산(`resolveHoldingValueKrw`)은 항상 `qty * price`이므로 `1 * 금액`이 곧 총액이 되어 기존 계산 로직을 전혀 바꿀 필요가 없었다.

## Consequences
- 현금성 자산을 다시 UI로 등록/수정할 수 있게 됐다 — `AGENTS.md`의 기존 "현금성 자산 등록 경로 없음" 메모는 이 결정으로 갱신됐다.
- `region`과 통화 체크박스가 사실상 같은 값을 가리키므로, 구분(국내/해외) select를 체크박스와 별도로 계속 조작할 수 있게 뒀다 — 바꾸면 체크박스 표시가 그에 맞춰 자동으로 따라간다(둘 다 `region` 하나에서 파생된 표시일 뿐이라 별도 동기화 로직이 필요 없다).
- 체크박스가 켜진 상태에서 코드 입력을 다시 켜는 경로는 없다 — 체크 해제가 유일한 복귀 방법이며, 그때 이전에 입력했던 티커/보유수량 텍스트가 남아있으면 그대로 복원된다(별도로 지우지 않음).
- 스키마 변경 없이 기존 `qty`/`avg_price` 컬럼 조합만으로 "금액 하나만 입력" UX를 구현했다 — 대신 DB에서 직접 조회하면 여전히 qty=1짜리 이상한 행처럼 보일 수 있다는 점은 감수한다.
