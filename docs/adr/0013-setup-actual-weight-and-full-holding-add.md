# ADR-0013: 설정 페이지 "실제 채워짐"을 진짜 실제 보유 비중으로 교체하고, 종목 추가 시 전체 항목을 함께 입력

## Status
Accepted

## Context
설정 페이지 상단의 "목표 배분"/"실제 채워짐" 두 바(ADR-0010)는 둘 다 목표 설정 자체의 완성도만 나타냈다 — 자산군 수준으로 100%를 채웠는지, 그걸 종목까지 다 쪼갰는지. 실제로 보유 중인 종목의 현재 시세 기준 비중은 전혀 반영되지 않았는데, "목표"/"실제"라는 이름은 비중 체크 페이지에서 "계획 vs 실제 보유 현황"을 비교할 때 쓰는 단어라 혼동을 줬다.

이걸 진짜 "계획 vs 실제 보유 비중" 비교로 바꾸면, 설정 페이지에서 새로 추가하는 종목도 처음부터 실제 데이터(보유수량/평균매입가/계좌/구분)를 가지고 있어야 이 비교가 의미가 있다. 그런데 기존 설정 페이지의 "+ 종목 추가"는 티커/종목명/그룹내비중만 입력받고 보유수량·평균매입가는 0으로 비워둔 채 만들어졌다 — 보유 종목 페이지에 따로 들어가서 채워야만 했다.

## Decision
- 설정 페이지 두 번째 바를 "실제 채워짐(종목까지)"에서 "실제 보유 비중"(각 자산군의 `actualPct`, 비중 체크 페이지와 동일한 라이브 시세 기반 계산)으로 교체했다. 뱃지도 "100%까지 남음"이 아니라 총 평가금액(또는 보유 데이터 없음)을 보여준다 — actualPct 합계는 항상 100%로 정규화되므로 "부족분" 개념이 적용되지 않는다.
- "종목까지 배분을 다 했는지"는 이미 각 자산군 카드의 그룹내 경고 문구로 별도 표시되고 있으므로 그대로 유지하고, 상단 요약에서는 제거했다.
- 설정 페이지에서 "+ 종목 추가"를 누르면 보유 종목 페이지와 동일한 `HoldingFormDialog`를 열어 티커/종목명/구분/계좌/보유수량/평균매입가/비고를 한 번에 입력받는다. 그룹 선택지는 draft 자산군들의 `clientKey`를 넘겨서, 모달에서 그룹을 고르더라도 실제 DB id가 아닌 로컬 draft 상태만 변경되도록 했다. 그룹 내 비중(targetPctInGroup)은 이 모달에 없으므로 0으로 시작하고, 추가된 뒤 인라인 행에서 조정한다.
- `lib/setupDraft.ts`의 `newDraftHolding`(빈 종목 생성)은 이제 쓰이지 않아 제거했고, 대신 `draftHoldingFromForm(holding: NewHolding)`으로 모달 제출값을 `DraftHolding`으로 변환한다.

## Consequences
- 설정 페이지에서 추가한 종목도 곧바로 실제 평가금액에 반영되어, "목표 배분"과 "실제 보유 비중" 두 바가 진짜 비교 가능한 지표가 됐다.
- 종목 추가 UI가 보유 종목 페이지와 통일되어 유지보수 지점이 하나로 줄었다.
- 기존 홀딩(이미 저장된 종목)의 보유수량/평균매입가를 설정 페이지에서 직접 고치는 기능은 이번 범위에 포함하지 않았다 — 여전히 보유 종목 페이지에서만 수정한다.
