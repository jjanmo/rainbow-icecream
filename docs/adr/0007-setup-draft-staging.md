# ADR-0007: 포트폴리오 설정 편집은 로컬 초안(draft) 방식, autosave 아님

## Status
Accepted

## Context
초기 설정 페이지 편집모드는 필드를 blur할 때마다 바로 Supabase에 저장했다. 사용자는 "완료" 버튼을 눌러야 실제로 반영되고, "취소"를 누르면 필드 수정뿐 아니라 자산군/종목 추가·삭제까지 포함해 편집 시작 전 상태로 완전히 되돌아가길 원했다. Autosave 구조로는 이걸 구현할 수 없었다.

## Decision
편집모드 진입 시 서버 데이터를 로컬 초안 상태(`DraftGroup[]`/`DraftHolding[]`)로 복사한다. 편집 중 모든 변경(필드 수정, 추가, 삭제)은 로컬 상태에만 반영되고 Supabase를 건드리지 않는다. "완료"를 누르면 원본과 초안을 비교해 실제로 바뀐 부분만 서버에 반영한다. "취소"는 서버 호출 없이 초안을 버린다.

## Consequences
- 서버 상태와 완전히 분리된 초안 데이터 모델과, 신규 항목의 임시 클라이언트 키 처리(신규 그룹 아래 신규 종목이 커밋 시점에 실제 group_id로 올바르게 연결되어야 함)가 필요하다.
- Supabase 클라이언트에서는 여러 테이블에 걸친 진짜 트랜잭션 롤백이 불가능하다 — 커밋 중간에 실패하면 일부만 반영된 상태가 될 수 있으므로, 이 경우 초안을 그대로 유지해 사용자가 재시도하도록 한다(완전 롤백은 범위 밖으로 명시적으로 받아들임).
- "완료"를 누르기 전까지는 다른 화면(보유 종목 등)에 이 편집 내용이 전혀 반영되지 않는다.
