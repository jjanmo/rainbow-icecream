# ADR-0049: 체결 목록 인라인 수정/삭제 버튼 복원, 수정 시 매매 구분 고정

## Status
Accepted

## Context

체결 목록을 표로 개편하면서(ADR-0041~0044 시기) 행을 클릭하면 상세 모달(`ExecutionDetailDialog`)이 뜨고, 그 안에 수정·삭제 버튼을 두는 구조로 만들었다. 그런데 상세 모달이 보여주는 정보(종목·일시·수량·단가·총액·실현손익·메모)는 표의 행이 이미 다 보여주고 있는 것과 사실상 같았다 — 모달이 별도로 존재할 이유가 없었다. "더 자세히 보기 위해" 만든 것이었는데, 표 자체가 이미 충분히 자세했다.

## Decision

**상세 모달을 없애고, 표 행 우측 끝에 수정/삭제 아이콘 버튼을 복원한다.** `HoldingsTable`/`HoldingsTableRow`가 쓰는 것과 같은 패턴(`Pencil`/`Trash2` 아이콘, `variant="ghost" size="icon-xs"`)이다. 수정은 기존 `ExecutionFormDialog`를 편집 모드로 그대로 열고, 삭제는 확인 없이 바로 지우던 예전 동작 대신 **확인 모달(`AlertDialog`)을 거치도록** 새로 추가했다 — 보유종목 삭제(ADR-0045)와 같은 패턴으로 맞췄다.

**수정 모드에서는 매수/매도를 고를 수 없다.** 예전 폼은 수정 모드에서도 매수/매도 토글 버튼이 그대로 남아있어서, 이미 저장된 체결의 매매 구분을 바꿀 수 있는 것처럼 보였다 — 하지만 매매 구분을 바꾸는 건 사실상 다른 종류의 체결로 다시 쓰는 것과 같고, 그러면 그 앞뒤 리플레이 의미도 달라진다. 종목 재배정을 지원하지 않는 것(ADR-0039)과 같은 이유로, 매매 구분도 지원하지 않기로 했다. 수정 모드에서는 토글 버튼 대신 지금 값(매수/매도)을 고정 라벨로만 보여준다. 구분을 잘못 기록했다면 지우고 다시 기록해야 한다.

`ExecutionDetailDialog.tsx`는 삭제했다 — 더 이상 쓰는 곳이 없다.

## Consequences

- `ExecutionsTable`의 `onRowClick` prop이 `onEdit`/`onDelete`로 바뀌었다 — 이 컴포넌트를 쓰는 곳(매매일지 메인 목록, ADR-0048의 "기초잔고 보기" 목록) 모두 두 콜백을 넘겨야 한다.
- 표 행에 더 이상 `cursor-pointer`/클릭 핸들러가 없다 — `OpeningBalanceBadge`가 클릭 버블링을 막으려 감싸뒀던 `<span onClick={stopPropagation}>`도 같이 걷어냈다(더 이상 막을 대상이 없다).
- 체결 하나를 고치는 화면(`ExecutionFormDialog`)이 수정 모드에서 렌더링하는 폼 모양이 신규 추가 모드와 달라졌다 — 매매 구분이 고정 라벨이라는 점만 다르고, 나머지 입력(종목 선택 불가 포함)은 기존과 동일하다.
