# ADR-0033: 근거·태그는 체결 입력 시트 안에서 접이식으로 받고, 매도 시 매수 근거를 배너로 띄운다

## Status
Accepted

## Context

ADR-0031이 `trade_notes` 스키마(EXECUTION/POSITION/DAY 분리, 구조화 태그 우선)를 정했지만, 입력 UI와 `trade_notes` API/훅은 없었다(`docs/journal-todo.md` "다음 작업 순서" 3번). PRD §3은 이 화면이 이 앱의 핵심 가치라고 명시한다 — "매도할 때는 그 종목을 살 때 적은 근거와 청산조건이 화면에 떠야 한다."

## Decision

**매수/매도 필드를 분리한다** (ADR-0031의 EXECUTION/POSITION 구분을 그대로 UI에 반영):
- **매수** → POSITION 노트(`targetKey = holding.id`): 셋업 태그, 청산조건, 손절가/목표가. 라지는 종목 전체에 유지돼야 하므로 매수 시점에만 입력받는다.
- **매도** → EXECUTION 노트(`targetKey = execution.id`): 감정 태그, 매도사유, "계획대로 했는가". 이 셋은 그 타이밍 하나에 대한 판단이라 매수 화면에는 노출하지 않는다.
- 자유 서술 메모는 공통.

**입력 시트 안, 기본 접힘.** 별도 화면으로 미루지 않고 `ExecutionFormDialog`에 "근거 추가" 접이식 섹션으로 넣는다 — 채우지 않아도 저장할 수 있어 PRD의 "체결 1건을 30초 안에" 요구를 지킨다. 아무것도 입력하지 않으면 `trade_notes` 행 자체를 만들지 않는다(빈 행 방지).

**매도 배너.** `side === 'SELL'`이고 기존 종목을 선택했을 때, 종목 선택 필드 바로 아래에 그 종목의 POSITION 노트를 조회해 셋업 태그·청산조건·손절가/목표가·메모를 보여준다. 없으면 "매수 시 기록된 근거가 없습니다"만 표시한다.

**저장은 upsert 하나로.** `trade_notes_target_idx`(user_id, target_type, target_key) 유니크 인덱스를 `onConflict`로 써서 생성/수정을 분기 없이 처리한다. POSITION 노트는 추가매수 때마다 재입력되며 이전 값을 덮어쓴다.

**부수 변경 — `commitNewExecution`이 생성된 체결을 반환하도록 수정.** 기존엔 `ReplayResult`만 돌려줬는데, EXECUTION 노트를 저장하려면 방금 생성된 체결의 `id`가 필요하다. `{ execution, replay }`로 반환 타입을 바꿨다(`lib/journal/commit.ts`). 근거 저장은 체결 저장과 별개 트랜잭션이라, 노트 저장이 실패해도 이미 성공한 체결은 롤백하지 않고 별도 토스트로만 알린다 — ADR-0027/0032가 이미 정한 "Supabase는 크로스 테이블 트랜잭션이 없다" 전제와 같은 태도다.

**DAY 노트는 이번 라운드에서 제외.** `lib/journal/noteTarget.ts`에 `dayNoteKey` 빌더는 만들어 뒀지만(스키마 주석이 이미 이 파일을 가리키고 있었다), 매매하지 않은 날의 관찰을 기록하는 UI는 journal-todo.md 3번 항목에 없어 붙이지 않았다.

**태그 자동완성.** 별도 API 없이 `fetchTradeNotes()`로 받은 전체 노트에서 `setupTags`를 클라이언트에서 집계한다(`holdings.tsx`의 `accountOptions` 파생과 동일 패턴). 감정 태그·매도사유는 이미 고정 열거형이라 자동완성이 필요 없고, 기존 "매매 의도" 칩과 같은 토글 버튼으로 처리했다 — 새 컴포넌트는 자유 입력이 필요한 셋업 태그(`TagInput`, 신규)에만 만들었다.

## Consequences

- 매수 시 남긴 라지/청산조건이 매도 순간 그대로 보여, "감정적 이탈"을 사용자 스스로 알아채게 만드는 장치가 실제로 동작한다.
- `commitNewExecution`의 시그니처 변경은 이 함수를 쓰는 다른 곳(`useAddExecution`)에는 영향이 없었다 — 반환값을 구조분해하지 않고 그대로 전달하는 위치였기 때문. 앞으로 이 함수를 호출하는 곳은 `{ execution, replay }` 형태를 기대해야 한다.
- POSITION 노트가 upsert라서, 같은 종목을 여러 번 추가매수하며 매번 근거 섹션을 채우면 마지막 입력이 이전 걸 덮어쓴다 — 라지가 시간이 지나며 바뀌는 걸 반영하는 의도된 동작이지만, "처음 세운 라지"를 보존하고 싶다면 별도 이력이 필요하다(v1 범위 밖).
- DAY 노트 UI, POSITION 노트를 매수 없이 단독으로 수정하는 경로(SC-3 상세/수정, journal-todo 4번)는 여전히 없다.

## 대안

- **별도 "근거 작성" 화면으로 분리**: PRD가 요구하는 "매도 화면에 근거가 뜨는" 인터랙션을 그 자체로 만족시키지 못하고, 입력 시점과 근거 작성 시점이 갈라져 기록률이 떨어진다. 기각.
- **감정 태그를 매수/매도 양쪽에 노출**: 근거 섹션이 두 배로 커지고, 사용자 확인 결과 매도 시점의 감정·복기만으로 충분하다고 판단해 기각.
